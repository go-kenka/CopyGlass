# 手动滚动截图（飞书式）设计

- 日期：2026-11-09
- 状态：已确认（用户确认：1) 滚动方向先做向上滚动；2) 点击「完成」后进入编辑模式，可标注，但不能重新截图、不能拖动/调整截图区域）

## 背景

现有 `ScrollingCaptureController` 是自动滚动：选完区域后把光标 warp 到选区中心，用 `CGEvent` 合成滚轮事件自己滚，用户完全无法控制。这与飞书的滚动截图交互不一致：飞书是在截图工具栏里点「滚动截图」，然后**用户自己滚**，边滚边拼，点「完成」结束。

## 目标交互

1. 普通截图流程不变：冻结屏幕 → 拖选区域 → 编辑工具栏。
2. 工具栏动作区新增「滚动截图」按钮（scroll 图标，位于文字识别/固定/保存/复制之前）。
3. 点击后：
   - 关闭冻结遮罩，把前台还给原来的应用（用户要滚的是它）；
   - 选区四周显示高亮取景框（点击穿透，绘制在选区外侧，不会被截进图里）；
   - 显示浮动 HUD：标题「滚动截图」、「完成」「取消」按钮、进度（已拼接帧数 / 高度 px）、提示文案；
   - 用户自己用触控板/滚轮滚动，应用持续抓帧并实时拼接；
   - 点「完成」/回车：关闭 HUD 与取景框，拼好的长图进入**编辑器窗口**；点「取消」/Esc：丢弃。
4. 菜单栏「滚动截图」和快捷键保留，语义改成：选完区域直接进入第 3 步（不用再点按钮）。
5. 完成后只能进入编辑器窗口做标注/OCR/复制/保存/固定；**不能重新截图，也不能拖动/调整截图区域**（长图没有冻结屏幕可重裁，编辑器本身也不提供这些操作）。

## 滚动方向

拼接模型使用「文档绝对坐标」：第一帧放在偏移 0，后续每帧通过行特征匹配得到与上一帧的带符号位移 d，把帧放到新的绝对位置。最终图片是所有帧的并集（最多 16000 px 高）。

- d > 0：内容上移（用户向下滚），向下扩展；
- d < 0：内容下移（用户向上滚），向上扩展；
- 来回滚动只会在已有范围内移动，不会重复或拉伸。

用户确认先以上滚为主要场景；模型天然支持双向，向上扩展有专门测试覆盖。

## 组件

| 单元 | 职责 |
|---|---|
| `ImageStitcher.estimateShift` | 纯函数：两帧行特征 → 带符号位移 d + 匹配误差。多锚点滑动窗口匹配，避开吸顶栏/滚动条 |
| `ScrollStitchSession` | 纯逻辑增量拼接器：吃帧、维护文档坐标与已存帧、输出结果状态，结束时一次性合成 |
| `ScrollingCaptureController` | 滚动会话：抓帧节奏、HUD/取景框生命周期、完成/取消、错误处理 |
| `ScrollingHUDController` | 悬浮 HUD（完成/取消、进度、提示） |
| `ScrollingBorderWindow` | 选区高亮取景框（穿透、外侧绘制、不进入截图） |
| `ScreenCaptureService` | 新增 `excluding:` 参数（排除自身 HUD/取景框窗口）与窗口号解析 |
| `RegionSelectionController` | 工具栏回调接入；purpose = .scroll 时选完直接进入滚动会话 |
| `ScreenshotToolbarView` | 新增滚动截图按钮 |
| `ScreenshotController` | 统一入口 `startScrolling(region:)` → 完成后打开编辑器 |

## 采集策略

- 滚动会话期间轮询抓帧：活跃时 10 fps，连续多帧无变化后降到约 4.5 fps（空闲省电），一有新内容立即恢复。
- 每帧复用 `ScreenCaptureService.captureRegion`（多显示器选区也能用），通过 `SCContentFilter(display:excludingWindows:)` 排除 HUD/取景框自身的窗口。
- 抓帧在后台，拼接在串行队列，UI 回主线程；同一时刻只允许一帧在飞行。

## 错误处理与边界

- 两帧重叠不足（滚太快）：该帧不入库、不破坏已有结果，HUD 提示「滚动太快，往回滚一点再继续」；往回滚可重新接上。
- 达到最大高度 16000 px：停止扩展，HUD 提示「已达最大长度，点击完成」，仍可点完成输出已有内容。
- 抓帧失败：首帧失败 → 取消并弹错误；后续偶发失败忽略。
- 没有滚动就点完成：返回选区首帧截图。
- 已有标注时点滚动截图：弹确认框提示会丢弃当前标注。
- 区域过小（宽或高 < 40）：不启动，仅提示音。
- 已知限制：吸顶页头/固定侧栏可能重复（与飞书一致）；页面自身动画/视频可能导致匹配失败并提示。
